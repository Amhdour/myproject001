# v0.1.0-portfolio-review Release Candidate Notes

## Summary

`v0.1.0-portfolio-review` is a draft portfolio review release candidate for the RAG and autonomous-agent security-readiness project. It packages reviewer navigation, evidence indexes, demo attack references, claim-boundary checks, and final GO/NO-GO language for professional review.

No real git tag is created by this document. These are draft release-candidate notes only.

## What is included

- Root portfolio positioning and reviewer path.
- Final case study and audience-specific review documents.
- Portfolio reviewer package under `/portfolio`.
- Synthetic demo attack package under `/demo_attacks`.
- CI-style portfolio and security-layer checks.
- Claim-boundary and fake-claim validation scripts.
- Release-prep package.
- Public-sharing audit package.
- Release-candidate package and evidence-side map.

## What reviewers can run

Reviewers can run:

```bash
python demo_attacks/run_demo_attacks.py
python scripts/portfolio/check_claim_boundary.py
python scripts/portfolio/check_no_fake_claims.py
python scripts/portfolio/check_evidence_links.py
python scripts/portfolio/check_public_sharing_readiness.py
python scripts/portfolio/check_release_candidate.py
python -m pytest backend/security_layer/tests -q
```

Passing commands support portfolio consistency and isolated helper behavior. They do not prove production-system readiness.

The release-prep package under [`portfolio/release_prep/`](../release_prep/README.md) contains draft release notes, reviewer checklists, screenshot/video checklists, and sanitization guidance. It does not create screenshots, video evidence, or live deployment proof.

## Public-sharing audit package

The public-sharing audit package under [`portfolio/public_sharing_audit/`](../public_sharing_audit/README.md) supports repository hygiene and safe sharing review. Public sharing remains conditional on manual review and sanitization.

## Safe claims

Safe claims include:

- This is a portfolio project.
- This is a production-style security-readiness demonstration.
- The work focuses on RAG and autonomous-agent trust and security readiness.
- The evidence package includes reviewer navigation, synthetic demo attacks, CI-style checks, and isolated security-layer tests.
- The repository documents known limitations and claim boundaries.

## Forbidden claims

Do not claim:

- production readiness;
- enterprise readiness;
- compliance certification;
- external validation;
- full Onyx live staging;
- live enforcement;
- live blocking;
- live filtering;
- real deployment proof unless real repository evidence exists.

## Known limitations

Known limitations remain documented in [`docs/security/known_limitations.md`](../../docs/security/known_limitations.md). Key limitations include no production-readiness claim, no enterprise-readiness claim, no external validation, no compliance certification, and no live enforcement/blocking/filtering claim.
