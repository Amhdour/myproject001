# Portfolio Runtime Security Claims

## Safe Positioning

This repository may be described as a **production-style AI Trust & Security Readiness portfolio for RAG and autonomous agent systems**.

Safe descriptions include:

- Onyx-based RAG and agent security-readiness portfolio;
- runtime-security evidence package;
- public-safe reviewer evidence room;
- RAG and agent security case study;
- controlled proof and claim-boundary demonstration;
- portfolio showing readiness discipline before production claims.

## Required Result Language

When describing Step 3, use the exact result:

`PASS_WITH_LIMITATIONS`

When describing readiness, use:

`~99% production-style portfolio coverage`

Always clarify that this is portfolio coverage, not production security coverage.

## Safe Claims

The portfolio can claim that it:

- documents RAG and autonomous-agent runtime-security risks;
- consolidates public-safe evidence for reviewer use;
- demonstrates claim-boundary discipline;
- identifies remaining operational validation work;
- separates portfolio readiness from production readiness;
- provides a demo narrative for prompt injection, retrieval, tool, MCP, and sensitive-data scenarios.

## Forbidden Claims

Do **not** claim:

- enterprise production readiness;
- external validation;
- full authenticated RBAC;
- full real-user tenant isolation;
- full real tool execution blocking;
- full real MCP server blocking;
- production deployment approval;
- compliance certification;
- full live enforce-mode coverage;
- that all Onyx request paths are protected;
- that all real user, document, tool, MCP, backup, restore, and incident-response paths have been validated.

## Suggested Reviewer Language

Use language like:

> This is a production-style AI Trust & Security Readiness portfolio for RAG and autonomous agent systems. Step 3 passed with limitations, and Phase 4 consolidates public-safe evidence into a reviewer-ready package. The project does not claim enterprise production readiness or external validation.
