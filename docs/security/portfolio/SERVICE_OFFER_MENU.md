# Service Offer Menu

## Services I Can Offer Now

These services fit the evidence and skill level demonstrated by this portfolio:

1. **AI security-readiness documentation review**
   - Review RAG or agent documentation for unsafe security claims, unclear assumptions, and missing limitations.
   - Produce a claim-boundary summary and safer public-facing language.

2. **RAG and agent risk-mapping workshop**
   - Map risks across prompt injection, retrieval, sensitive-data exposure, tool use, MCP-style integrations, and tenant boundaries.
   - Deliver a prioritized risk register and recommended evidence plan.

3. **Portfolio-style evidence package creation**
   - Convert scattered notes, tests, screenshots, and findings into a structured reviewer evidence room.
   - Separate what is proven from what remains future validation.

4. **Demo and interview narrative preparation**
   - Help transform technical AI-security work into a clear demo path, case study, and interview script.
   - Keep language conservative and evidence-backed.

5. **Claim-boundary and public-share readiness audit**
   - Identify wording that could imply enterprise production readiness, external validation, compliance certification, deployment approval, or stronger security coverage than the evidence supports.
   - Provide corrected language and a safe publishing checklist.

6. **Pre-assessment gap analysis for RAG/agent systems**
   - Review existing security-readiness artifacts and identify missing tests, missing evidence, and unclear ownership.
   - Produce a practical next-step roadmap.

## Services I Should Not Offer Yet

These services would require stronger credentials, operational authority, independent validation scope, or deeper production access than this portfolio claims:

- enterprise production readiness certification;
- compliance certification or audit sign-off;
- external auditor validation;
- production deployment approval;
- full authenticated RBAC assurance;
- full real-user tenant-isolation assurance;
- full real tool execution blocking assurance;
- full real MCP server blocking assurance;
- incident-response retainer services without a qualified operational team;
- legal, regulatory, or formal compliance advice.

## Discovery-Call Questions

Use these questions to scope a client conversation:

1. What type of AI system are you reviewing: RAG, autonomous agent, workflow agent, chatbot, or mixed system?
2. What sensitive data can the system retrieve, generate, transform, or expose?
3. Which users, roles, tenants, or workspaces must remain isolated?
4. Does the system call tools, APIs, plugins, MCP servers, code execution, browsers, or workflow automations?
5. What security claims are already being made in sales, documentation, demos, or internal status reports?
6. What evidence exists today: tests, logs, screenshots, design docs, threat models, reviews, or issue trackers?
7. What is the intended output: public portfolio, internal readiness review, investor/customer narrative, or engineering gap list?
8. Are there constraints around sharing logs, screenshots, credentials, hostnames, user data, or customer data?
9. Who will review the final package: recruiters, technical hiring managers, security leaders, customers, auditors, or engineers?
10. What stronger claims are desired later, and what validation would be needed before making them?
