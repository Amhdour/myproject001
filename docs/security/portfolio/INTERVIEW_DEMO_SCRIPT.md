## Likely Interview Questions and Answers

### Q1: What does `PASS_WITH_LIMITATIONS` mean here?

It means the Step 3 runtime-security evidence is strong enough for a reviewer-facing portfolio, but it still has documented gaps before stronger operational claims are appropriate. It is not a claim of enterprise production readiness, external validation, compliance certification, or production deployment approval.

### Q2: What does `~99% production-style portfolio coverage` mean?

It means the portfolio package is nearly complete as a career/reviewer artifact: evidence is organized, claim boundaries are documented, demo paths are clear, and remaining work is explicit. It does not mean 99% production security coverage, compliance coverage, enterprise deployment readiness, or operational approval.

### Q3: Why not just say the system is secure?

Because that would overstate the evidence. RAG and agent systems need specific validation across users, tenants, retrieval paths, tools, MCP servers, incident response, and production operations. This portfolio demonstrates readiness discipline, but it does not claim complete security assurance.

### Q4: What security risks did you focus on?

The portfolio focuses on prompt injection, unsafe retrieval, sensitive-data exposure, tool misuse, MCP-style integration risk, RBAC and tenant-boundary concerns, evidence quality, and public claim safety.

### Q5: What makes this useful to a team?

It shows how to turn messy AI-security work into a structured evidence package that stakeholders can review. It also reduces the risk of overclaiming by separating proven evidence from planned validation.

### Q6: What would need to happen before stronger production claims?

The project would need authenticated RBAC validation, seeded real-document retrieval tests, real configured tool execution tests, real MCP server execution tests, stronger route polish, external validation, backup/restore drills, incident-response drills, and production-operations review.

### Q7: Did an external auditor validate this?

No. External validation is not claimed. It remains future work.

### Q8: Does this prove full tenant isolation?

No. Full real-user tenant isolation is not claimed. The portfolio identifies tenant-boundary risk and remaining validation needs, but stronger real-user and real-document isolation evidence would be required.

### Q9: Does this prove tools and MCP servers are blocked in production?

No. Full real tool execution blocking and full real MCP server blocking are not claimed. Those require real configured tool and MCP server execution tests before stronger claims are appropriate.

### Q10: How would you explain the project to a non-security stakeholder?

I would say it is a structured evidence package that shows how an AI system was reviewed for important RAG and agent risks, what is supported by evidence, and what still needs validation before anyone should make stronger production or compliance claims.
